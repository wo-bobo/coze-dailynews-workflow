# Coze 智能体：每日资讯简报自动化（DailyNews 工作流）

> 用 Coze 把「人工检索 → 筛选 → 汇总 → 推送」这条每天都要做的重复流程，改造成**无人值守自动运行**的工作流。

**核心设计：一条工作流，两种触发方式。**

| 触发方式 | 场景 | 行为 |
| --- | --- | --- |
| **定时触发** | 每天早上的固定需求 | 每天 **8:00** 自动抓取热点资讯 → 清洗汇总成简报 → 推送给用户 |
| **按需触发** | 用户主动想问某个话题 | 用户提问时调用同一条工作流，即时返回最新汇总 |

两种触发复用同一套节点逻辑，维护成本只有一份——改一次清洗规则或输出格式，定时任务和即时问答同时生效。

---

## 一、为什么这么做

原本的做法是每天手动重复四步：**打开资讯源 → 逐条浏览筛选 → 复制粘贴汇总 → 发给自己或群里**。

问题不在于单次耗时长，而在于**它是每天都发生的固定动作**，属于典型的"高频、低价值、纯人工"流程——最适合交给工作流。

改造后的目标很明确：**零人工触达**，且简报迟到比没有更糟（所以定时触发设在早 8:00），保证用户起床就能看到。

## 二、工作流结构

```
┌─────────────────┐
│  触发器          │
│  ① 定时 每天8:00 │──┐
│  ② 用户提问      │──┤
└─────────────────┘  │
                     ▼
        ┌────────────────────────┐
        │ 1. 资讯获取            │  抓取指定来源的热点/最新资讯
        └────────────────────────┘
                     ▼
        ┌────────────────────────┐
        │ 2. 清洗与筛选          │  去重、按关键词/领域过滤、取 Top N
        └────────────────────────┘
                     ▼
        ┌────────────────────────┐
        │ 3. 大模型汇总          │  结构化输出：标题 + 要点 + 简评
        └────────────────────────┘
                     ▼
        ┌────────────────────────┐
        │ 4. 输出与推送          │  定时：推送到对话/群
        │                        │  按需：直接返回本次结果
        └────────────────────────┘
```

## 三、关键节点说明

### 1. 触发器设计

- **定时触发器**：Cron 表达式按每天 8:00 触发。选择这个时间点是因为简报的价值在于"起床即可读"，早于用户起床时间完成。
- **按需触发**：同一个工作流可以被对话直接调用，用户问"今天有什么新消息"时会走同一套抓取与汇总逻辑，只是输出直接回到对话里，不走推送。

> 一条工作流支撑两种触发，是这套设计里最省事的部分：后续只要优化清洗规则，两条路径同时受益。

### 2. 清洗与筛选

抓回来的原始资讯包含重复、广告、无关领域内容，直接丢给大模型会得到"看起来像简报但全是水"的结果。因此中间必须有一层筛选：**去重 → 领域/关键词过滤 → 取 Top N**，控制进入大模型的资讯量，既保证质量也控制 token 成本。

### 3. 汇总输出

用大模型做结构化汇总，而不是让它"自由发挥"：固定输出为「标题 + 1~2 句要点」的形式，保证每天的简报版式一致，方便快速扫读。

## 四、效果

| 对比项 | 改造前 | 改造后 |
| --- | --- | --- |
| 触发方式 | 人记得手动做 | 每天 8:00 自动运行 |
| 人工介入 | 检索 + 筛选 + 汇总 + 推送全人工 | **零人工触达** |
| 即时查询 | 需要自己再翻一遍 | 直接问，按需返回 |
